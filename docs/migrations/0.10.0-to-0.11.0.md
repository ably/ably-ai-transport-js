# Migrate from 0.10.0 to 0.11.0

## Why 0.11.0 changes

In 0.10.0, the transport sat between your application and the Ably channel. It resolved the channel from your client, owned its options, attached and detached it, and delivered each message to your subscribe handler. Your application could not use the channel the way it uses any other Ably channel, and the transport had to grow an option for every channel feature an application wanted.

0.11.0 implements [AITRFC-032](https://ably.atlassian.net/wiki/spaces/AI/pages/5536645151). Your application holds the channel through the Ably Pub/Sub SDK, and AI Transport supplies two helpers that work on that channel:

- **An agent adaptor** publishes a provider's events on a channel you give it. It takes the place of the transport's `send` and `pipe`.
- **A decoder** turns each message your own `channel.subscribe` handler receives, live or from history, back into the provider's events. It takes the place of the transport's `subscribe` and `history`.

The codecs do not change their rows, but they no longer hold state. The decoder holds the state that a streaming reader needs.

## What replaces each 0.10.0 API

| 0.10.0                                                            | 0.11.0                                                                                  |
| :---------------------------------------------------------------- | :-------------------------------------------------------------------------------------- |
| `createTransport({ client, channelName, codec })`                 | `client.channels.get(channelName)`, then an adaptor and a decoder on it                 |
| `transport.send(event, { headers })`                              | `adaptor.send(event, { headers })`                                                      |
| `transport.pipe(source, { signal, headers })`                     | `adaptor.pipe(source, { signal, headers })`, or `adaptor.pipeEach` to act on each event |
| `transport.subscribe(handler)`                                    | `decoder.onEvent(handler)` and `channel.subscribe(decoder.receive)`                     |
| `transport.history({ limit })`                                    | `channel.history({ untilAttach: true, limit })`, each message through `decoder.decode`  |
| `subscribe(handler, { history: { replay: fromSerial(serial) } })` | Your own history loop; see below                                                        |
| `untilEvent(predicate)`                                           | Your own history loop                                                                   |
| `transport.on('error', handler)`                                  | `decoder.onError(handler)`                                                              |
| `transport.on('discontinuity', handler)`                          | `channel.on(handler)`, through ably-js                                                  |
| `transport.close()`                                               | `channel.unsubscribe(decoder.receive)`; the adaptor holds nothing to close              |
| `createTransport({ codec: vercel })`                              | `vercelAdaptor(channel)` and `vercelDecoder()`                                          |
| `createTransport({ codec: openai })`                              | `openaiAdaptor(channel)` and `openaiDecoder()`                                          |
| `createTransport({ codec: agui })` or `createAGUICodec()`         | `agUiAdaptor(channel)` and `agUiDecoder()`                                              |
| A custom codec passed to `createTransport`                        | `createAgentAdaptor(channel, codec)` and `createDecoder(codec)`                         |
| `channelModes`, `OBJECT_MODES` and `echoMessages`                 | Channel options you pass to `channels.get` yourself                                     |
| `@ably/ai-transport/react`                                        | ably-js's `<AblyProvider>` and `<ChannelProvider>`, with a decoder in an effect         |

## Upgrade the client and the agent together

The wire format changes. Every message the SDK writes is now named `ai` and carries the codec's id under `extras.ai.codec`, and a decoder skips any message without both. A 0.11.0 decoder therefore ignores messages that a 0.10.0 agent published, and an AG-UI message that 0.10.0 named `ag-ui` is now named `ai`. Deploy the agent and the clients together, and expect history written by 0.10.0 to decode with no events.

## Move the agent to an adaptor

```typescript
// 0.10.0
const transport = createTransport({ client: ably, channelName, codec: vercel });
try {
  await transport.pipe(stream, { signal, headers });
} finally {
  await transport.close();
}

// 0.11.0
const adaptor = vercelAdaptor(ably.channels.get(channelName));
await adaptor.pipe(stream, { signal, headers });
```

`pipe` keeps its contract. It resolves with the serial of its last publish, it rejects with `OperationCancelled` or `PipeFailed`, and it flushes and repairs what it wrote before it settles. An adaptor can also carry default headers, `vercelAdaptor(channel, { headers })`, which a call's headers override.

`pipeEach` is new. It hands each event back once it is written, with the serial of the message the event landed on:

```typescript
for await (const { event, serial } of adaptor.pipeEach(stream, { signal })) {
  if (event.type === 'finish') await db.saveReplySerial(serial);
}
```

When the source ends, `pipeEach` flushes and repairs like `pipe`. Leaving the loop early or firing the signal stops it where it is, with no flush, no repair and no closing message, so a client sees a stream that was cut off stay open.

## Move the client to a decoder

```typescript
// 0.10.0
const transport = createTransport({ client: ably, channelName, codec: vercel });
const unsubscribe = transport.subscribe(apply);
transport.on('error', report);

// 0.11.0
const channel = ably.channels.get(channelName);
const decoder = vercelDecoder();
decoder.onEvent(apply);
decoder.onError(report);
await channel.subscribe(decoder.receive);
// later: channel.unsubscribe(decoder.receive)
```

A delivery is still `{ event, message }`, and every message still comes back as at least one delivery. A message that is not the codec's comes back with `event: undefined`. Use one decoder per channel, and pass it both the live messages and the history messages, so that it decodes a message that both carry only once.

The transport attached the channel on the first `subscribe` and detached it on `close`. ably-js does the same when you call `channel.subscribe`, and you decide when to detach.

## Catch up from history with your own loop

`fromSerial` and `untilEvent` are removed. Page `channel.history({ untilAttach: true })` back to the point you need, pass each message to `decoder.decode`, and apply the result oldest first. To show history before live without duplicates, decode live messages as they arrive and hold the deliveries while you read history:

```typescript
const held: Delivery<VercelEvent>[] = [];
let live = false;
await channel.subscribe((message) => {
  const deliveries = decoder.decode(message);
  if (live) deliveries.forEach(apply);
  else held.push(...deliveries);
});

const newer: Ably.InboundMessage[] = [];
let page: Ably.PaginatedResult<Ably.InboundMessage> | null = await channel.history({ untilAttach: true });
while (page) {
  newer.push(...page.items.filter((m) => (m.serial ?? '') > stored.serial));
  if (page.items.some((m) => (m.serial ?? '') <= stored.serial) || !page.hasNext()) break;
  page = await page.next();
}

newer
  .map((m) => decoder.decode(m))
  .toReversed()
  .flat()
  .forEach(apply);
held.forEach(apply);
live = true;
```

History pages arrive newest first, and the decoder is built to take them in that order. `demo/minimal/src/app/chat.tsx` is the full version.

## Replace the React entry point

`@ably/ai-transport/react` is removed, with `TransportProvider`, `useTransport`, `useDeliveries`, `useHistory` and `useTransportStatus`. Mount `<AblyProvider>` and `<ChannelProvider>` from `ably/react`, get the channel from the client, and subscribe a decoder in an effect. `useChannelStateListener` from `ably/react` reports the channel's state.

## Update codec code

- `Codec.adapterTag` is now a required `id`, and `defineCodec` takes `id` in place of `adapterTag`.
- `defineCodec` no longer takes `name` or `logger`, and a row can no longer name its message. The adaptor names every message `ai`.
- A built codec no longer holds a decoder core, so calling `codec.decode` directly gives you no tail reduction and no replay guard. Use `createDecoder(codec)` for that.
- `createDecoderCore` is no longer exported.
- `vercel`, `createVercelCodec`, `openai`, `createOpenAICodec`, `agui` and `createAGUICodec` are no longer exported. Use the provider's adaptor and decoder factories.

## Attribution

The transport registered an Ably-Agent entry when it resolved the channel from your client. An adaptor receives a channel and never sees the client, so 0.11.0 sends no Ably-Agent attribution.

## Update error code checks

| 0.10.0                                                                                                                                                 | 0.11.0                            |
| :----------------------------------------------------------------------------------------------------------------------------------------------------- | :-------------------------------- |
| `SessionSubscriptionFailed` (104001), `SessionClosed` (104004), `SessionHistoryFetchFailed` (104011)                                                   | Removed                           |
| `InvalidArgument`, `OperationCancelled`, `InsufficientCapability`, `InternalError`, `StreamedMessageFinalizeFailed`, `SessionSendFailed`, `PipeFailed` | Unchanged                         |
| `SessionMessageProcessingFailed`                                                                                                                       | Now reported on `decoder.onError` |
