# Migrate from 0.11.0 to 0.12.0

## Why 0.12.0 changes

In 0.11.0, the transport sat between your application and the Ably channel. It resolved the channel from your client, owned its options, attached and detached it, and delivered each message to your subscribe handler. Your application could not use the channel the way it uses any other Ably channel, and the transport had to grow an option for every channel feature an application wanted.

0.12.0 implements [AITRFC-032](https://ably.atlassian.net/wiki/spaces/AI/pages/5536645151). Your application holds the channel through the Ably Pub/Sub SDK, and AI Transport supplies two helpers that work on that channel:

- **An agent adaptor** publishes a provider's events on a channel you give it. It takes the place of the transport's `send` and `pipe`.
- **A decoder** turns each message your own `channel.subscribe` handler receives, live or from history, back into the provider's events. It takes the place of the transport's `subscribe` and `history`. 0.11.0 already ships the decoder, so an application that reads the channel itself is already using it.

The wire format does not change from 0.11.0, so a 0.11.0 agent and a 0.12.0 client can share a channel, and you can upgrade the agent and the clients independently.

## Update the packages

```sh
npm install @ably/ai-transport@0.12.0
```

`react` is no longer a peer dependency, because the React entry point is removed. `@ably/pubsub-server` and `@ably/pubsub-device` stay optional peers, as in 0.11.0.

## What replaces each transport API

| 0.11.0                                                            | 0.12.0                                                                                                         |
| :---------------------------------------------------------------- | :------------------------------------------------------------------------------------------------------------- |
| `createTransport({ client, channelName, codec })`                 | `client.channels.get(channelName)`, then an adaptor and a decoder on it                                        |
| `transport.send(event, { headers })`                              | `adaptor.send(event, { headers })`                                                                             |
| `transport.pipe(source, { signal, headers })`                     | `adaptor.pipe(source, { signal, headers })`, or `adaptor.pipeEach` to act on each event                        |
| `transport.subscribe(handler)`                                    | `decoder.onEvent(handler)` and `channel.subscribe(decoder.receive)`                                            |
| `transport.history({ limit })`                                    | `channel.history({ untilAttach: true, limit })`, each message through `decoder.decode`                         |
| `subscribe(handler, { history: { replay: fromSerial(serial) } })` | Rewind the channel to the serial; see below                                                                    |
| `untilEvent(predicate)`                                           | A loop over `channel.history`, stopping where your predicate matches                                           |
| `transport.on('error', handler)`                                  | `decoder.onError(handler)`                                                                                     |
| `transport.on('discontinuity', handler)`                          | `channel.on(handler)` on the channel itself; see below                                                         |
| `transport.close()`                                               | `channel.unsubscribe(decoder.receive)`; the adaptor holds nothing to close                                     |
| `createTransport({ codec: vercel })` or `createVercelCodec()`     | `vercelAdaptor(channel)` and `vercelDecoder()`                                                                 |
| `createTransport({ codec: openai })` or `createOpenAICodec()`     | `openaiAdaptor(channel)` and `openaiDecoder()`                                                                 |
| `createTransport({ codec: agui })` or `createAGUICodec()`         | `agUiAdaptor(channel)` and `agUiDecoder()`                                                                     |
| A custom codec passed to `createTransport`                        | `createAgentAdaptor(channel, codec)` and `createDecoder(codec)`                                                |
| `channelModes`, `OBJECT_MODES` and `echoMessages`                 | Channel options you pass to `channels.get` yourself                                                            |
| `@ably/ai-transport/react`                                        | `<PubSubClientProvider>` and `<ChannelProvider>` from `@ably/pubsub-device/react`, with a decoder in an effect |

## Move the agent to an adaptor

```typescript
// 0.11.0
const transport = createTransport({ client: pubsubClient, channelName, codec: vercel });
try {
  await transport.pipe(stream, { signal, headers });
} finally {
  await transport.close();
}

// 0.12.0
const adaptor = vercelAdaptor(pubsubClient.channels.get(channelName));
await adaptor.pipe(stream, { signal, headers });
```

`pipe` keeps its contract. It resolves with the serial of its last publish, it rejects with `OperationCancelled` or `PipeFailed`, and it flushes and repairs what it wrote before it settles. An adaptor can also carry default headers, `vercelAdaptor(channel, { headers })`, which a call's headers override.

`pipeEach` is new. It returns each event once it is written, with the serial of the message the event was written to:

```typescript
for await (const { event, serial } of adaptor.pipeEach(stream, { signal })) {
  if (event.type === 'finish') await db.saveReplySerial(serial);
}
```

`pipeEach` flushes and repairs like `pipe` however the loop ends: the source ending, a failure, the signal, or leaving the loop early. A stop writes no closing message, so a client sees a stream that was cut off stay open. A `ReadableStream` source is released, not cancelled, so stop the model call yourself if it should stop too.

## Move the client to a decoder

```typescript
// 0.11.0
const transport = createTransport({ client: pubsubClient, channelName, codec: vercel });
const unsubscribe = transport.subscribe(apply);
transport.on('error', report);

// 0.12.0
const channel = pubsubClient.channels.get(channelName);
const decoder = vercelDecoder();
decoder.onEvent(apply);
decoder.onError(report);
await channel.subscribe(decoder.receive);
// later: channel.unsubscribe(decoder.receive)
```

A delivery is still `{ event, message }`, and every message still comes back as at least one delivery. A message that is not the codec's comes back with `event: undefined`. Use one decoder per channel, and pass it both the live messages and the history messages, so that it decodes a message of an open stream that both carry only once. Once a stream's closer has been decoded, the decoder forgets the stream, so either decode history before live messages, holding the live deliveries until history is done, since `untilAttach` needs the channel attached and subscribed first, or rewind the channel to a serial so one subscription delivers both in order.

The transport attached the channel on the first `subscribe` and detached it on `close`. The Pub/Sub SDK does the same when you call `channel.subscribe` on a channel from `channels.get`, and you decide when to detach. Under `<ChannelProvider>` from `@ably/pubsub-device/react`, subscribe does not attach, so call `channel.attach()` yourself after subscribing.

The transport reported a discontinuity when the channel went FAILED, SUSPENDED or DETACHED, or reached ATTACHED or UPDATE with `resumed: false`. Watch for the same state changes with `channel.on`. To catch up, read your store again, detach the channel, and rewind it to the serial the store returns with `channel.setOptions({ params: { rewind } })`, as the next section describes. `demo/minimal` does this whenever its channel loses continuity.

## Catch up with rewind to a serial

`fromSerial` and `untilEvent` are removed. To catch up from a serial your store holds, rewind the channel to it when you get the channel:

```typescript
const channel = pubsubClient.channels.get(
  channelName,
  stored.serial === undefined ? undefined : { params: { rewind: stored.serial } },
);
const decoder = vercelDecoder();
decoder.onEvent(apply);
await channel.subscribe(decoder.receive);
```

Set the param on the first `channels.get` for the channel. For a channel that is already attached, `channels.get` with a different `rewind` throws, and `channel.setOptions` is the call that changes it.

On attach, the platform delivers every message after the serial, then live messages, in channel order, so the decoder sees each message once and in order. The serial's own message is not replayed. A message that was appended to arrives first as one full-content update. Rewind delivers at most 1,000 messages after the serial, and applies only when the channel attaches. `demo/minimal/src/app/page.tsx` and `chat.tsx` are the full version.

## Replace the React entry point

`@ably/ai-transport/react` is removed, with `TransportProvider`, `useTransport`, `useDeliveries`, `useHistory` and `useTransportStatus`. Keep `<PubSubClientProvider>`, and mount `<ChannelProvider>` from `@ably/pubsub-device/react` in place of `<TransportProvider>`. Get the channel from the client, and in an effect subscribe a decoder and then call `channel.attach()`, since `<ChannelProvider>` turns off attach on subscribe. `useChannelStateListener` from `@ably/pubsub-device/react` reports the channel's state.

## Update codec imports

`vercel`, `createVercelCodec`, `openai`, `createOpenAICodec`, `agui` and `createAGUICodec` are no longer exported. Use the factories named after each codec: `vercelAdaptor()` and `vercelDecoder()` in place of `vercel` or `createVercelCodec()`, `openaiAdaptor()` and `openaiDecoder()` in place of `openai` or `createOpenAICodec()`, and `agUiAdaptor()` and `agUiDecoder()` in place of `agui` or `createAGUICodec()`. `vercelAdaptor()` and `vercelDecoder()` take the same type parameters as `createVercelCodec()`. `Codec`, `defineCodec`, `createAgentAdaptor` and `createDecoder` stay on the root entry point for a format of your own.

## Attribution

The transport registered an Ably-Agent entry when it resolved the channel from your client. An adaptor receives a channel and never sees the client, so 0.12.0 sends no Ably-Agent attribution.

## Loading AI Transport from a script tag

The AI Transport bundle carries the core entry point only, so a page that loads it from a script tag builds its codec with `defineCodec`. The Vercel, OpenAI and AG-UI adaptors and decoders need a bundler.

```js
const client = AblyPubSub.createClient({ authUrl: '/api/auth/token' });
const codec = AblyAiTransport.defineCodec({
  id: 'my-format',
  typeOf: (e) => e.type,
  events: {
    /* one row per event type */
  },
});
const decoder = AblyAiTransport.createDecoder(codec);
client.channels.get(channelName).subscribe(decoder.receive);
```

## Update error code checks

| 0.11.0                                                                                                                                                 | 0.12.0                                                                                |
| :----------------------------------------------------------------------------------------------------------------------------------------------------- | :------------------------------------------------------------------------------------ |
| `SessionSubscriptionFailed` (104001), `SessionClosed` (104004), `SessionHistoryFetchFailed` (104011)                                                   | Removed                                                                               |
| `InvalidArgument`, `OperationCancelled`, `InsufficientCapability`, `InternalError`, `StreamedMessageFinalizeFailed`, `SessionSendFailed`, `PipeFailed` | Unchanged                                                                             |
| `SessionMessageProcessingFailed`                                                                                                                       | Reported on `decoder.onError`, where 0.11.0's transport forwarded it to `on('error')` |
