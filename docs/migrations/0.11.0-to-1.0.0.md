# Migrate from 0.11.0 to 1.0.0

## Why 1.0.0 changes

In 0.11.0, the transport resolved the Ably channel from your client, owned its options, attached and detached it, and delivered each message to your subscribe handler. Your application could not use the channel the way it uses any other Ably channel, and the transport needed a new option for every channel feature an application wanted.

In 1.0.0, your application gets the channel from its Ably Pub/Sub client, and AI Transport supplies two helpers that work on that channel:

- **An agent adaptor** publishes a provider's events on a channel you give it. It replaces the transport's `send` and `pipe`.
- **A decoder** turns each message your `channel.subscribe` handler receives, live or from history, back into the provider's events. It replaces the transport's `subscribe` and `history`. 0.11.0 already ships the decoder, so an application that reads the channel itself can keep using it.

The wire format is the same as in 0.11.0, so a 0.11.0 agent and a 1.0.0 client can share a channel, and you can upgrade the agent and the clients independently.

## Update the packages

```sh
npm install @ably/ai-transport@1.0.0
```

`react` is no longer a peer dependency, because 1.0.0 removes the React entry point. `@ably/pubsub-server` and `@ably/pubsub-device` stay optional peers, as in 0.11.0.

## What replaces each transport API

| 0.11.0                                                            | 1.0.0                                                                                                                                                                                                                                              |
| :---------------------------------------------------------------- | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `createTransport({ client, channelName, codec })`                 | `client.channels.get(channelName)`, then an adaptor and a decoder on the channel                                                                                                                                                                   |
| `transport.send(event, { headers })`                              | `adaptor.send(event, { headers })`                                                                                                                                                                                                                 |
| `transport.pipe(source, { signal, headers })`                     | `adaptor.pipe(source, { signal, headers })`, or `adaptor.pipeEach` to act on each event                                                                                                                                                            |
| `transport.subscribe(handler)`                                    | `decoder.onEvent(handler)` and `channel.subscribe(decoder.receive)`                                                                                                                                                                                |
| `transport.history({ limit })`                                    | `channel.history({ untilAttach: true, limit })` on an attached channel, with each message passed to `decoder.decode`; items arrive newest first                                                                                                    |
| `subscribe(handler, { history: { replay: fromSerial(serial) } })` | [Rewind the channel](#catch-up-with-rewind-to-a-serial) to the serial                                                                                                                                                                              |
| `untilEvent(predicate)`                                           | A loop over `channel.history` that stops where your predicate matches                                                                                                                                                                              |
| `transport.on('error', handler)`                                  | `decoder.onError(handler)`                                                                                                                                                                                                                         |
| `transport.on('discontinuity', handler)`                          | `channel.on(handler)`, a [channel state listener](#move-the-client-to-a-decoder)                                                                                                                                                                   |
| `transport.close()`                                               | `channel.unsubscribe(decoder.receive)`, then `channel.detach()`; a running pipe stops through its `signal`                                                                                                                                         |
| A custom codec passed to `createTransport`                        | `createAgentAdaptor(channel, codec)` and `createDecoder(codec)`                                                                                                                                                                                    |
| `channelModes` and `OBJECT_MODES`                                 | `modes` in the channel options you pass to `channels.get`, listing every mode the channel needs. For LiveObjects, that is `['PUBLISH', 'SUBSCRIBE', 'PRESENCE', 'PRESENCE_SUBSCRIBE', 'ANNOTATION_PUBLISH', 'OBJECT_PUBLISH', 'OBJECT_SUBSCRIBE']` |
| `echoMessages: false`                                             | `params: { echo: 'false' }` in the channel options you pass to `channels.get`                                                                                                                                                                      |
| `@ably/ai-transport/react`                                        | `<PubSubClientProvider>` and `<ChannelProvider>` from `@ably/pubsub-device/react`, with a decoder subscribed in an effect                                                                                                                          |

## Move the agent to an adaptor

```typescript
// 0.11.0
const transport = createTransport({ client: pubsubClient, channelName, codec: vercel });
try {
  await transport.pipe(stream, { signal, headers });
} finally {
  await transport.close();
}

// 1.0.0
const adaptor = vercelAdaptor(pubsubClient.channels.get(channelName));
await adaptor.pipe(stream, { signal, headers });
```

`pipe` keeps its contract. It resolves with the serial of its last publish, it rejects with `OperationCancelled` or `PipeFailed`, and it flushes and repairs what it wrote before it settles.

An adaptor can also take default headers, as in `vercelAdaptor(channel, { headers })`. Where a call's headers and the adaptor's default headers both set a value, the call's value is used.

`pipeEach` is new. It yields each event back to the agent once the adaptor has written it, with the serial of the message that holds the event. In this example, `saveResponseSerial` is your application's function that writes the serial to your database, so a client can later rewind the channel to it:

```typescript
for await (const { event, serial } of adaptor.pipeEach(stream, { signal })) {
  if (event.type === 'finish') await saveResponseSerial(serial);
}
```

`pipeEach` flushes and repairs like `pipe` however the loop ends: the LLM event stream ending, a failure, the signal, or leaving the loop early. If the signal fires or the loop exits early, the adaptor does not publish a closing message, so a subscribed client sees the stream stay open. The agent should then publish a terminal event with `adaptor.send`, such as `{ type: 'abort' }` for the Vercel AI SDK. The adaptor releases a `ReadableStream` source without cancelling it, so the agent should pass the same signal to the model call to stop the model call too.

## Move the client to a decoder

In this example, `apply` and `report` are your application's handlers for deliveries and errors:

```typescript
// 0.11.0
const transport = createTransport({ client: pubsubClient, channelName, codec: vercel });
const unsubscribe = transport.subscribe(apply);
transport.on('error', report);

// 1.0.0
const channel = pubsubClient.channels.get(channelName);
const decoder = vercelDecoder();
decoder.onEvent(apply);
decoder.onError(report);
await channel.subscribe(decoder.receive);
// later: channel.unsubscribe(decoder.receive)
```

A delivery is still `{ event, message }`, and every message still comes back as at least one delivery. A message that is not the codec's comes back with `event: undefined`.

Your application should use one decoder per channel for both live and history messages, so the decoder decodes a message of an open stream only once when both carry it. After the decoder decodes the message that ends a stream, it forgets the stream, so a copy of that stream that arrives later decodes again. To avoid duplicate events, your application should give the decoder history before live messages. There are two ways to do this:

- **Rewind the channel to a serial**, so one subscription delivers history and then live messages in order. `demo/minimal` uses this approach, and [rewind to a serial](#catch-up-with-rewind-to-a-serial) has the code.
- **Decode history first.** Your application subscribes a handler that buffers the raw live messages, pages `channel.history({ untilAttach: true })` through `decoder.decode`, and then passes the buffered messages to `decoder.receive`. `untilAttach` needs the channel attached, so your application subscribes first.

The transport attached the channel on the first `subscribe` and detached it on `close`. In 1.0.0, `channel.subscribe` attaches the channel, and your application should call `channel.detach()` when it no longer needs the channel.

The transport reported a discontinuity when the channel became FAILED, SUSPENDED, or DETACHED, or on an ATTACHED or UPDATE state change with `resumed: false`. Your application can watch for state changes with `channel.on`, and should treat DETACHED, FAILED, and an ATTACHED or UPDATE change with `resumed: false` as a discontinuity. A SUSPENDED channel keeps its serial, so its next attach normally resumes, and an ATTACHED change with `resumed: false` follows if it does not.

If your application stores a serial, it can catch up after a discontinuity. It should unsubscribe the decoder, detach the channel so that the next attach applies the new rewind, and read your database again. It then gets the channel with a rewind to the serial your database returns, and subscribes a new decoder, as the next section shows. `demo/minimal` does this.

## Catch up with rewind to a serial

1.0.0 removes `fromSerial` and `untilEvent`. To catch up from a serial in your database, your application can rewind the channel to that serial when it gets the channel. In this example, `stored` is what your application read from your database:

```typescript
const channel = pubsubClient.channels.get(
  channelName,
  stored.serial === undefined ? undefined : { params: { rewind: stored.serial } },
);
const decoder = vercelDecoder();
decoder.onEvent(apply);
await channel.subscribe(decoder.receive);
```

Rewind applies only when the channel attaches, so your application should set the `rewind` param on the first `channels.get` for the channel. For a channel that is already attached, `channels.get` with a different `rewind` throws, and `channel.setOptions` is the call that changes it.

When the channel attaches, Ably delivers up to 1,000 messages after the serial, then live messages, in channel order, so the decoder sees each message once. Ably does not replay the message at the serial itself. A message that was appended to arrives first as one update with its full content.

`demo/minimal/src/app/page.tsx` and `chat.tsx` have a full example.

## Replace the React entry point

1.0.0 removes `@ably/ai-transport/react` and its exports `TransportProvider`, `useTransport`, `useDeliveries`, `useHistory` and `useTransportStatus`.

Your app should keep `<PubSubClientProvider>`, and mount `<ChannelProvider>` from `@ably/pubsub-device/react` where it mounted `<TransportProvider>`. In an effect, it should get the channel from the client, subscribe a decoder, and then call `channel.attach()`, because `<ChannelProvider>` turns off attach on subscribe. `useChannelStateListener` from `@ably/pubsub-device/react` reports the channel's state.

A Vercel AI SDK app that uses `useChat` can pass [`createChatTransport`](../../README.md#usechat) from `@ably/ai-transport/vercel` as its transport in place of that effect. The chat transport subscribes its own decoder and attaches the channel if nothing else has.

## Update codec imports

1.0.0 removes the `vercel`, `createVercelCodec`, `openai`, `createOpenAICodec`, `agui` and `createAGUICodec` exports. Each codec has an adaptor factory and a decoder factory in their place:

| 0.11.0                            | 1.0.0                                   |
| :-------------------------------- | :-------------------------------------- |
| `vercel` or `createVercelCodec()` | `vercelAdaptor()` and `vercelDecoder()` |
| `openai` or `createOpenAICodec()` | `openaiAdaptor()` and `openaiDecoder()` |
| `agui` or `createAGUICodec()`     | `agUiAdaptor()` and `agUiDecoder()`     |

`vercelAdaptor()` and `vercelDecoder()` take the same type parameters as `createVercelCodec()`. `Codec`, `defineCodec`, `createAgentAdaptor` and `createDecoder` stay on the root entry point for a custom wire format.

## Attribution

The transport registered an Ably-Agent entry when it resolved the channel from your client. An adaptor receives a channel and never sees the client, so 1.0.0 does not send Ably-Agent attribution.

## Loading AI Transport from a script tag

The AI Transport bundle for a script tag holds the core entry point only, so a page that loads it should build its codec with `defineCodec`. The Vercel, OpenAI, and AG-UI adaptors and decoders need a bundler.

```js
const client = AblyPubSub.createClient({ authUrl: '/api/auth/token' });
const codec = AblyAiTransport.defineCodec({
  id: 'my-format',
  typeOf: (e) => e.type,
  events: {
    /* one row per event type */
  },
});
const decoder = AblyAiTransport.createDecoder(codec);
decoder.onEvent(apply);
client.channels.get(channelName).subscribe(decoder.receive);
```
